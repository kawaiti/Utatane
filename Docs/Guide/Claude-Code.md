# Claude Codeを操作する

ゴーストを通して、パソコン上のClaude Codeに指示を出す機能です。指示は文字入力のほか、ホットキーを押している間に話す音声でも出せます。進み具合と結果の要約はゴーストが話し、全文と詳細は専用ウィンドウに表示します。

ファイルの書き換えやコマンドの実行は、原則として画面か声で許可を求めます。ただし、権限モードを「編集を自動許可」にした場合のファイル編集や、Claude Codeのユーザー設定で許可済みの操作など、確認なしで実行される場合があります。詳しくは「[承認](#承認)」と「[確認なしで実行される場合](#確認なしで実行される場合)」を読んでください。

## 準備

- `claude`コマンド（Claude Code CLI）をインストールし、ターミナルで一度`claude`を起動してログインを済ませてください。ログインしていない場合、ゴーストは「Claude Codeにログインしていません。ターミナルで claude を起動してログインしてください」と話します。Utataneは`~/.local/bin/claude`、`/opt/homebrew/bin/claude`、`/usr/local/bin/claude`、`~/.claude/local/claude`の順に探します。見つからない場合や別の場所に置いている場合は、設定でパスを指定します。
- 「本体設定」→「Claude Code」で作業ディレクトリを選びます。Claude Codeはこのフォルダを作業場所として起動します。未選択のままでは起動せず、設定画面を開きます。
- メニューバーの「操作」→「Claude Code…」でウィンドウを開きます。下部の入力欄に指示を入力して送信します。

## 設定

「本体設定」→「Claude Code」にあります。

| 項目 | 内容 |
| --- | --- |
| 音声入力を有効にする | 既定はオフです。オフの間は、マイクと音声認識の許可を要求せず、ホットキーも登録しません。文字入力は音声入力がオフでも使えます。 |
| 復唱確認 | 既定はオンです。音声で聞き取った指示を読み上げ、「はい」と答えてから送ります。オフにすると、聞き取った指示をそのまま送ります。文字入力は復唱しません。 |
| ホットキー | 押している間だけ聞き取ります。`Control + Option + Space`、`右Option（長押し）`、`fn（長押し）`から選びます。 |
| claudeのパス | 既定は自動検出です。「選択…」で指定し、「クリア」で自動検出へ戻します。 |
| 作業ディレクトリ | Claude Codeを動かすフォルダです。 |
| モデル | 空欄ならClaude Codeの既定のモデルを使います。入力すると`--model`として渡します。 |
| 権限モード | 「確認しながら」または「編集を自動許可」。「編集を自動許可」では、ファイルの編集を確認せずに許可します。どちらのモードでも、ユーザー設定（`~/.claude/settings.json`）で許可済みの操作は確認なしで実行されることがあります。 |

ホットキーの動きは次のとおりです。

- `Control + Option + Space`: 3つのキーを同時に押した時点で聞き取りを始め、スペースキーを離すと終わります。
- `右Option`と`fn`: 約0.35秒押し続けると聞き取りを始め、離すと終わります。押している間に別のキーを打った場合は、聞き取りを始めません。通常の修飾キーとしての使い方は妨げません。
- 1回の押下で聞き取れるのは最長60秒です。60秒を過ぎると、キーを離したものとして聞き取りを終えます。キーを離したことをUtataneが受け取れなかった場合に、マイクが入ったままにならないようにするための動作です。

権限モードは、Claude Codeの`--permission-mode`へそのまま渡します。

- 確認しながら（`default`）: ファイルの編集やコマンドの実行のたびに、承認を求めます。
- 編集を自動許可（`acceptEdits`）: ファイルの編集はClaude Code側で自動的に許可し、Utataneは確認を求めません。コマンドの実行は引き続き承認を求めます。

設定の反映は次のとおりです。

- 音声入力のオン・オフとホットキーは、すぐに反映します。音声入力をオフにすると、聞き取り中の内容は使わずに捨てます。
- claudeのパス、作業ディレクトリ、モデル、権限モードは、次の指示から反映します。Claude Codeを新しい設定で起動し直し、その作業ディレクトリで前回使った会話を再開します。作業ディレクトリを切り替えた場合は、切り替え先のフォルダで前回使った会話を再開します。
- 作業中に設定を変えた場合、新しい設定での起動はいまの指示が終わるまで待たされ、その間に送った指示には「作業中です」と表示します。

## 会話（セッション）

Claude Codeとの会話は、作業ディレクトリごとに記録します。Utataneを終了して起動し直しても、同じ作業ディレクトリでは前回の会話の続きから指示できます（Claude Codeの`--resume`を使います）。

新しい会話を始めるには、Claude Codeウィンドウの「新しいセッション」を押します。いまの作業ディレクトリの記録を消し、次の指示から新しい会話になります。作業中は押せません。前回の会話を再開できずに失敗が続く場合も、「新しいセッション」を使ってください。

## 指示の出し方

### 文字で出す

Claude Codeウィンドウの入力欄に入力して送信します。復唱はありません。作業中は「中断」ボタンで止められます。

### 声で出す

音声入力を有効にしたうえで、次の順に操作します。

1. ホットキーを押したまま、指示を話します。途中で息継ぎや間があっても、キーを押している間に話した内容は1つの発話としてまとめます。
2. キーを離すと、聞き取った内容をウィンドウに表示します。何も聞き取れなかった場合は、ゴーストが「聞き取れませんでした」と話します。
3. 復唱確認がオンなら、ゴーストが「『…』と指示します。よろしいですか?」と読み上げます。「はい」で送信、「いいえ」で取りやめます。もう一度ホットキーを押して答えてください。
4. 作業が始まると、ゴーストが進み具合を話し、終わると結果を要約して話します。

指示を送ったあとも、次のように話しかけられます。

- 「止めて」「とめて」「中断」「ストップ」: いつでも作業を中断します。「止めてください」のように「ください」を付けても同じです。
- 「やめて」（「やめてください」）: 復唱や承認の返事を待っている間は「いいえ」として扱い、それ以外のときは作業を中断します。
- 作業中に別の指示を話すと、ゴーストが「作業中です」と答え、その指示は送りません。作業中に「はい」「いいえ」と話した場合も、返事を待っていなければ同じです。
- 復唱や承認の返事を待っている間は、「はい」「いいえ」と中断の言葉だけを受け付けます。それ以外を話すと「聞き取れませんでした」と答え、指示としては扱いません。
- 作業中でも返事待ちでもないとき（待機中）に話した「はい」「いいえ」は、通常の指示として扱われます。

「はい」は「許可」「OK」「オーケー」「いいよ」「実行」「お願いします」も、「いいえ」は「拒否」「だめ」「やめて」「キャンセル」も同じ扱いです。いずれも、その言葉だけを話した場合に限ります。音声認識は日本語（`ja-JP`）です。

Claude Codeには、日本語で3文以内に要約して答えるよう伝えています。詳しい内容はウィンドウで確認してください。

## 承認

Claude Codeがファイルの書き換えやコマンドの実行をしようとすると、ウィンドウに許可を求める表示が出て、ゴーストが内容を読み上げます。表示には、実際に実行されるコマンドやファイルのパスを示します。

- 読み取り専用のツール（`Read`、`Glob`、`Grep`、`LS`）は、確認なしで許可します。
- 書き込みや`Bash`などは、ウィンドウの「許可」「拒否」ボタンか、声の「はい」「いいえ」で答えます。
- 危険なコマンドは、許可を求めずにその場で拒否します。許可を求める表示は出ず、ボタンでも声でも許可できません。詳しくは次の「危険なコマンド」を参照してください。
- 45秒以内に答えなかった場合は、拒否として扱います。中断した場合も拒否です。
- 読み取り専用のツールは、作業ディレクトリの外にあるファイルも確認なしで読めます。
- ホットキーを押している最中に許可の表示が出た場合、そのときの発話では答えられません。いったん離し、もう一度押して話してください。前の確認に対する返事が新しい確認へ届かないようにするための動作です。

### 危険なコマンド

`Bash`で実行しようとしたコマンドが危険と判定されると、Utataneは許可を求めずにすぐ拒否し、Claude Codeには「危険なコマンドのため実行できません」と返します。ウィンドウに止めたコマンドを赤く表示し、ゴーストが「危険なコマンドなので実行できません」と話します。ボタン、声、待ち時間のどれを使っても許可はできません。どうしても必要な操作は、内容を確かめたうえでご自身のターミナルで実行してください。

危険と判定するのは、おおむね次のようなコマンドです。

- 削除や上書き: `rm`、`dd`、`shred`、`truncate`、`unlink`、`mkfs`や`newfs_apfs`などのフォーマット、`diskutil`の消去やパーティション操作、再帰的な`chmod`・`chown`・`chgrp`、`rimraf`（`npx rimraf`を含む）、`rsync --delete`や`--remove-source-files`
- 権限やシステムの操作: `sudo`、`doas`、`shutdown`、`reboot`、`halt`、`launchctl unload`・`remove`・`bootout`、`killall`、`pkill`、すべてのプロセスへの`kill -1`、`crontab -r`、`defaults delete`、`security delete-…`、`tmutil delete`や`deletelocalsnapshots`
- 取り消しにくいGit操作: `git push`、`git clean`、`git reset --hard`、`git branch -D`、`git checkout -- .`のように変更を捨てる`git checkout`、`git restore`（`--staged`だけで取り消す場合を除く）、`git stash drop`・`clear`、`git rm -r`（`--cached`を除く）、`git reflog expire`、`git gc --prune`、`git filter-branch`、`git update-ref -d`
- 文字列や入力から別のコマンドを実行する書き方: `bash -c`のようにシェルへ文字列を渡す書き方、`bash <<< …`や`sh <<EOF`のようなヒアストリングやヒアドキュメント、`| sh`・`| /bin/bash`・`| env bash`のようなシェルへのパイプ、`eval`、`xargs`、`env -S`、`find`の`-delete`や`-exec`

`\rm`や`"rm"`のように引用符やバックスラッシュを付けた書き方、`/bin/rm`のようなパス付きの書き方、`FOO=1 rm`のような変数の指定、`env`・`nice`・`timeout`・`nohup`・`time`・`xcrun`などの前置きも見分けます。`if … then`・`for … do`・`while`の中、`( … )`や`{ …; }`でまとめた中、`!`の後ろ、`$( … )`の中にあるコマンドも判定します。

この判定は、コマンドの文字列から推測する簡易な仕組み（ヒューリスティック）です。実行を隔離する仕組みではありません。

判定は安全側に倒しているため、次のような実際には安全なコマンドも止めます。必要なら、別の書き方を指示するか、ご自身のターミナルで実行してください。

- `bash -c ls`のように、無害な内容をシェルへ文字列で渡す書き方
- `xargs`と`eval`のすべての使い方、`find … -exec`
- `git checkout -- ファイル名`のように、1つのファイルの変更を捨てる操作
- 引用符の中の`;`、`&`、`|`、`(`、`)`で区切られた部分（`echo "a; rm"`や`echo "(rm)"`など）や、前置きのあとの引数（`timeout 5 echo rm`など）

反対に、次のような書き方は検出できません。危険と判定されなかったコマンドも、許可する前に中身をよく読んでください。

- バッククォートによるコマンド置換（`` `rm x` ``）
- 行末の`\`で行をつないだ書き方（`r\`の次の行に`m -rf x`）、`$'\x72m'`のような`$'…'`形式の引用、`{rm,-rf,x}`のようなブレース展開
- `> ファイル名`によるファイルの上書き（中身が消えます）
- `python -c`、`perl -e`、`node -e`、`osascript`、`awk`の`system()`のように、ほかの言語やプログラムへコードを渡す書き方
- `$CMD`のように変数から組み立てたコマンド
- 同じコマンド内で定義したエイリアスや関数
- `-r`を付けない`git rm`など、上に挙げていない削除や変更の操作、上に挙げていない前置き

### 確認なしで実行される場合

Utataneの承認と危険なコマンドの拒否は、Claude Codeが許可を求めたときにだけ働きます。次の場合は、Utataneの確認を経ずに実行されることがあります。危険と判定されるコマンドでも同じです。

- 権限モードが「編集を自動許可」のときのファイル編集。
- Claude Codeのユーザー設定（`~/.claude/settings.json`）にある許可ルール（`permissions.allow`など）で許可済みの操作や、`PreToolUse`フックが許可した操作。
- 読み取り専用のツール（`Read`、`Glob`、`Grep`、`LS`）による読み取り。作業ディレクトリの外のファイルも対象です。

作業ディレクトリの`.claude/settings.json`と`.claude/settings.local.json`は読み込みません。Claude Codeを`--setting-sources user`で起動し、ユーザー設定だけを使うためです。この指定はClaude Codeの公式ドキュメントに基づいており、実際の`claude`での動作確認は済んでいません。また、プロジェクト設定を読まないため、そのフォルダ向けの設定（プロジェクトで共有している許可ルールやフックなど）は反映されません。

## 必要な権限

- マイクと音声認識: 音声入力を有効にして初めてホットキーを押したとき、macOSが許可を求めます。許可しないと聞き取れません。音声入力がオフなら、どちらも要求しません。
- アクセシビリティ: 別のアプリを使っている間もホットキーを使うために必要です。音声入力を有効にしたとき、未許可ならウィンドウに案内を一度だけ表示します。「システム設定」→「プライバシーとセキュリティ」→「アクセシビリティ」でUtataneを許可してください。未許可の間は、Utataneがアクティブなときだけホットキーが効きます。

## 開発ビルド（Debug）で使う

承認の中継には、補助プログラム`utatane-mcp`を使います。リリースビルドではアプリ内（`Contents/Helpers`）に同梱しますが、Debugビルドには同梱しません。補助プログラムが見つからない間は、承認を経由せずにClaude Codeが動くことがないよう、起動を取りやめます。「承認用のヘルパーが見つかりません」と表示されます。

Debugビルドで試すには、補助プログラムをビルドし、環境変数`UTATANE_MCP_PATH`にそのパスを指定してUtataneを起動します。環境変数はアプリの起動時に設定する必要があり、指定したファイルは存在して実行可能でなければなりません。`open -a Utatane`のようにシェルの環境変数を引き継がない起動方法では効きません。

```sh
swift build --package-path packages --product utatane-mcp
# 実行ファイルを直接起動する場合（Utatane.appはDebugビルドの場所に読み替えてください）
UTATANE_MCP_PATH="$PWD/packages/.build/debug/utatane-mcp" /path/to/Utatane.app/Contents/MacOS/Utatane
# または open の --env を使う場合
open --env UTATANE_MCP_PATH="$PWD/packages/.build/debug/utatane-mcp" /path/to/Utatane.app
```

Xcodeから実行する場合は、「Scheme」→「Run」→「Arguments」→「Environment Variables」へ`UTATANE_MCP_PATH`を追加し、値に上のパスを指定します。

## 制限

- 同時に動かせるセッションは1つです。作業中は新しい指示を送れません。
- Claude Codeが起動直後に終了した場合は、Claude Codeが出したエラー出力の末尾（最大4KB）をウィンドウの結果に表示します。ゴーストは最初の1行だけを話します。
- Finderから起動したUtataneでも`npm`で入れた`claude`が動くよう、`claude`のあるフォルダ、`/opt/homebrew/bin`、`/usr/local/bin`を`PATH`の先頭に加えて起動します。
- 音声認識はmacOS標準のエンジン（日本語）のみです。ほかのエンジンは選べません。
- 承認の要求は同時に1件だけ扱います。
- Claude Codeの出力形式と承認の応答形式は、公式ドキュメントの記述に基づいて実装しています。実機での全項目の確認は済んでいません。`claude`の更新で動作が変わる可能性があります。
